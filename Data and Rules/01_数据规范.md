# 01 数据规范 v1.0.0

- 适用范围：`data/`、`eval/` 下的全部数据文件，以及生成这些文件的 `core/gen_data.py`
- 机器可读版本：`data_schema_v1.yaml`（表结构）、`enums.yaml`（枚举与编号格式）、`gen_profile_v1.yaml`（生成参数）
- 本文与 YAML 不一致时，以 YAML 为准，并当天修正本文

---

## 1. 文件清单

| 文件 | 必需 | 工具可读 | 说明 |
|---|---|---|---|
| `data/accounts.csv` | 是 | 是 | 账户表 |
| `data/transactions.csv` | 是 | 是 | 交易表，不含任何标签 |
| `data/dataset_meta.json` | 是 | 是 | 数据集身份证：编号、规范版本、生成参数、种子、行数、哈希 |
| `eval/answer.csv` | 是 | **否** | 账户级答案 |
| `eval/answer_tx.csv` | 建议 | **否** | 交易级答案，用于评测链边的准确度 |

“工具可读”指 `core/api.py`、`core/trace.py`、`core/rules.py`、`core/ticket.py`、`core/rejudge.py` 和 `mcp_server/` 可以打开的文件。`eval/` 只允许 `core/evaluate.py`、`core/selfcheck.py`、`core/gen_data.py`、`core/verify_injected_chains.py`（以及后期的 `core/import_amlsim.py`）引用。`validate_spec.py --check-leak` 会扫描代码中是否出现 `eval/`、`answer`。

## 2. CSV 通用格式

| 项 | 约定 |
|---|---|
| 编码 | UTF-8，**无 BOM**（用 pandas 写：`to_csv(path, index=False, encoding="utf-8", lineterminator="\n")`） |
| 换行 | LF |
| 分隔与表头 | 逗号分隔，第一行为表头，列名全小写英文 |
| 引号 | 只在值含逗号、引号、换行时加双引号 |
| 空值 | 空串。必填列不得为空 |
| 时间 | `YYYY-MM-DD HH:MM`，精确到分钟，Asia/Shanghai 本地时间，不带时区后缀 |
| 同一分钟内的顺序 | 按 `tx_id` 升序 |
| 金额 | 单位元，币种 CNY。**读取方必须按数值处理并接受最多 2 位小数**；v1 生成器只输出正整数 |
| 列顺序 | 必需列按本文顺序在前，可选列在后。读取方按列名取值，不得依赖列位置 |
| 未知列 | 读取方必须忽略不认识的可选列，不得报错 |

## 3. 编号

| 对象 | 格式（正则） | v1 实际 | 说明 |
|---|---|---|---|
| 账户 | `^A\d{4,}$` | `A0001`~`A0300` | 类型随机分配（seed 控制），涉案账户不得集中在连号段 |
| 交易 | `^T\d{5,}$` | `T00001` 起 | 全表按 (time, 原始生成顺序) 排序后统一编号，编号随时间单调递增 |
| 现金出口 | `CASH` | 固定值 | 只能作为 `tx_type=提现` 的 `to_acct`；不在 accounts.csv 中 |
| 外部对手 | `^EXT-[A-Z]\d{4,}$` | 不出现 | 预留给跨机构扩展，如 `EXT-B0001` |
| 答案链路 | `^C\d{2,}$` | `C01`~`C12` | **只出现在 `eval/`** |
| 系统链路 | `^L-T\d{5,}$` | 如 `L-T00412` | `L-` + 链内最小交易号，见 02 规范第 5 节 |
| 工单 | `^TK-v\d+-A\d{4,}$` | 如 `TK-v1-A0087` | |

“允许变宽”的含义：数据量扩大后可以出现 `A10001`、`T123456`，读取方和正则不得写死位数（例如乙的 `check_ids.py` 要用 `T\d{5,}`）。第一周固定为 4 位和 5 位。

## 4. 表结构

### 4.1 `data/accounts.csv`

| 列 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `acct_id` | 字符串 | 是 | 唯一，符合账户编号格式 |
| `name` | 字符串 | 是 | 合成名：个人 `用户0001`、商户 `商户001`、企业 `企业01`（序号为该类型内序号），不用真实姓名 |
| `acct_type` | 枚举 | 是 | `个人` / `商户` / `企业` |
| `open_date` | 日期 `YYYY-MM-DD` | 是 | 不晚于数据起始日 |

预留可选列：`bank_code`（开户机构，跨机构扩展用）、`region`、`kyc_level`、`status`（账户状态，与研判状态无关）。

### 4.2 `data/transactions.csv`

| 列 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `tx_id` | 字符串 | 是 | 唯一 |
| `time` | 时间 | 是 | 在 `dataset_meta.time_range` 内 |
| `from_acct` | 字符串 | 是 | 必须存在于 accounts.csv |
| `to_acct` | 字符串 | 是 | 必须存在于 accounts.csv，或为 `CASH`（仅提现） |
| `amount` | 数值 | 是 | > 0 |
| `tx_type` | 枚举 | 是 | `转账` / `工资` / `消费` / `提现`（`退款`、`跨行转出`、`分账` 为预留值，v1 不出现） |

预留可选列：`currency`、`channel`、`memo`、`device_id`、`balance_after`、`src_ref`（外部来源交易号）。

禁止出现的列（两张数据表都适用）：`chain`、`chain_id`、`pattern`、`role`、`label`、`is_fraud`、`is_sar`、`alert_id`。

### 4.3 交易类型约束

| tx_type | 付款方类型 | 收款方类型 | 说明 |
|---|---|---|---|
| 转账 | 任意 | 任意账户 | 风险规则主要统计对象 |
| 工资 | 企业 | 个人 | 只用于反向规则 R09 |
| 消费 | 个人 | 商户 | R02、R10 使用 |
| 提现 | 任意 | `CASH` | 不进入追链，只在工单中作为缺口 `GAP_EXT` 的依据 |

其他约束：不得自转（`from_acct ≠ to_acct`）；交易日期不早于双方开户日期；文件按 `(time, tx_id)` 升序。

v1 不存余额。R04“余额清零”用当日流入流出比近似，若以后提供 `balance_after`，可新增规则实现而不改 R04 的含义。

### 4.4 `data/dataset_meta.json`

结构见 `schemas/dataset_meta.schema.json`，样例见 `examples/data/dataset_meta.json`。必填：

| 字段 | 说明 |
|---|---|
| `dataset_id` | `sim-{profile}-seed{seed}`，如 `sim-gen_profile_v1-seed42` |
| `spec_version` | 本规范版本，如 `1.0.0` |
| `source` | `synthetic`（自研生成）；以后可为 `amlsim`、`mixed` |
| `profile` | 生成配置名，如 `gen_profile_v1` |
| `generator` | 生成脚本路径，如 `core/gen_data.py` |
| `seed` | 随机种子 |
| `time_range` | `[起, 止]`，规则 R05 的“数据起始日”取 `time_range[0]` 的日期 |
| `timezone`、`currency`、`amount_unit` | `Asia/Shanghai`、`CNY`、`元` |
| `row_counts` | `{accounts: n, transactions: n}` |
| `sha256` | `{accounts.csv: ..., transactions.csv: ...}` |

**不得包含**：生成时间（保证同 seed 两次生成的文件完全一致）、链路数量、任何答案信息。

### 4.5 `eval/answer.csv`

| 列 | 必填 | 约束 |
|---|---|---|
| `acct_id` | 是 | 存在于 accounts.csv |
| `chain_id` | 涉诈行必填 | `C01` 等；干扰行留空 |
| `pattern` | 是 | 涉诈：`快进快出` / `分层中转` / `拆分转出`；干扰：`工资` / `商户` / `合租转发` |
| `role` | 是 | `疑似受骗付款端` / `一级收款端` / `中转端` / `拆分端` / `末端` / `无` |

- 键：`(acct_id, chain_id)`。v1 一个账户最多一行；以后允许同一账户出现在多条链上。
- 涉诈行：`role ≠ 无`；同一 `chain_id` 的行 `pattern` 相同。干扰行：`chain_id` 为空、`role = 无`。
- 答案角色与系统角色用同一套判定（03 规范第 3 节），例如分层中转的 L1 登记为 `一级收款端`，L2、L3 为 `中转端`。
- 2 名 `EMP_MULES` 只登记其所在链的行，不再登记 `工资` 行，所以“纯员工”为 28 人。
- 不出现在 answer.csv 中的账户为“背景账户”，评测时单列（03 规范第 7 节）。

### 4.6 `eval/answer_tx.csv`（建议）

`tx_id, chain_id`：每条埋入链路中账户到账户的 `转账` 交易。提现到 `CASH` 不列入（追链不含现金边）。

## 5. pattern 与 role 代码

CSV 中写中文值，代码中可用 `enums.yaml` 里的英文代码。

| pattern | 代码 | 类别 | 状态 |
|---|---|---|---|
| 快进快出 / 分层中转 / 拆分转出 | P01 / P02 / P03 | 涉诈 | 启用 |
| 汇聚转入 / 快速取现 / 循环回流 | P04 / P05 / P06 | 涉诈 | 预留 |
| 工资 / 商户 / 合租转发 | B01 / B02 / B03 | 干扰 | 启用 |
| 家庭代付 / 理财赎回 | B04 / B05 | 干扰 | 预留 |

role 代码：`VICTIM_PAYER`、`FIRST_RECEIVER`、`RELAY`、`SPLITTER`、`COLLECTOR`（汇聚端，预留）、`TERMINAL`、`NONE`。不用 `R0`~`R6` 这类代码，避免与规则号混淆。

## 6. 防泄题

1. 标签只能出现在 `eval/`，数据表禁止出现标签列（第 4.2 节）。
2. `dataset_meta.json` 不含答案信息。
3. 知识库文件（`kb/`）不出现账户号、交易号。
4. `core/api.py` 等工具代码不得引用 `eval/`，用 `python "Data and Rules/validate_spec.py" --check-leak core mcp_server` 检查。

## 7. 生成配置要点（`gen_profile_v1.yaml`）

完整参数见 YAML，这里只列原因。

| 项 | 取值 | 原因 |
|---|---|---|
| 个人互转 | 1400 笔，50~2000 元，08:00~21:59 | 低于链边最小金额 3000，不会被追成链；R01/R04 要求转入 ≥10000，也不会命中 |
| R02 窗口 | 60 分钟（不是 24 小时） | 蒙特卡罗（20 次）：24 小时窗口下约 120 个普通个人命中 R02，60 分钟窗口下约 2 个；5 家高频商户仍全部命中，普通商户约 3/25 命中 |
| 高频商户 | 5 家，每天 30~34 笔，10~300 元，同日付款方不重复 | 触发 R02，再由 R10 给出反向证据 → 证据不足 |
| 普通商户 | 25 家，每周 10~20 笔，付款方不重复 | 付款方 ≥10，R10 成立 |
| 受骗方金额 | 每人 25000~50000 | 使 R08（>20000）对链头生效；C03 的夜间转账 >10000，使 R06 生效 |
| 一级收款端转出比例 | 0.96~1.0 | 高于 R04 的 0.95，避免取整后掉到阈值以下 |
| 首笔转入到首笔转出 | v1 检出链 ≤55 分钟；C05/C06 为 70~110 分钟 | v1 窗口 60、v2 窗口 120，留出 5 分钟余量 |
| 链上账户“静默期” | 链路首笔前、末笔后各 180 分钟内，并扩大到链路所在自然日的全天（`quiet_scope: natural_day`），无其他转账往来 | 背景小额转账混入会改变 R01 的比例；R04 按自然日统计出入比，当天混入约 1000 元转入就会掉到 0.95 以下，导致结果随 seed 波动 |
| 首次对手 | 同一条链上任意两个账户之间，除链上交易外无任何交易 | 保证 R08、R11 稳定 |
| R02 防护 | v2 演示链（C05、C06）的受骗方和 D3 三方，背景转入不得在 60 分钟内凑满 3 个来源（`r02_guard`，参数取 `rules_v1` 的 R02） | 这些账户的 v1 预期为“未见异常”，背景偶然命中 R02 会使预期随 seed 漂移 |
| 新开户 | 一级收款端、中转端、拆分端约一半，开户于数据起始日前 10~25 天 | R05 |
| D3 合租转发 | 10500 转入，90 分钟后转出 9800 | 比例 0.933：v2 的 R01 命中（≥0.9），R04 不命中（<0.95），所以 v1 未见异常，v2 证据不足 |
| D3 的工资 | 来自另一家企业 | 不占用 30 名员工名额；该企业在答案表登记为 `工资` |

总量：个人互转 1400 + 高频商户约 1120（5 家 × 7 天 × 30~34）+ 普通商户约 375 + 工资 31 ≈ 2930 笔背景交易；12 条链约 55~70 笔（含提现），D3 2 笔；合计约 3000 笔。

可复现：同一 profile、同一 seed 两次生成，三个 data 文件的 sha256 必须相同。所有随机量走同一个 `random.Random(seed)`，不得遍历无序集合。

## 8. 扩展约定

| 扩展 | 怎么做 | 是否兼容 1.x |
|---|---|---|
| 加字段 | 在可选列中登记后直接加 | 兼容 |
| 金额带小数 | 读取方已按数值处理，生成器改输出即可 | 兼容 |
| 更多账户、交易 | 编号自然变宽 | 兼容 |
| 新交易类型（退款等） | `enums.yaml` 中从 reserved 改 active，并在 `tx_type_parties` 中登记双方类型 | 兼容；规则默认不统计新类型，需在规则的 `in_types`/`out_types` 中显式加入 |
| 跨机构 | 启用 `EXT-` 前缀与 `bank_code` 列 | 兼容 |
| 多个数据集 | 每个数据集一个 `dataset_meta.json`，`dataset_id` 区分；评测结果注明 `dataset_id` | 兼容 |
| 改列名、删列、改枚举中文值 | 不允许 | 须升 2.0，并经甲乙双方同意 |

### 8.1 AMLSim 接入（后期）

AMLSim 输出的是带标签的账户表、交易表和告警表。接入时写一个独立的 `core/import_amlsim.py`，遵守以下原则，具体列名以所用 AMLSim 版本的实际输出为准：

1. 输出仍是本规范的三个 data 文件 + 两个 eval 文件，`dataset_meta.source = amlsim`，`profile` 写导入配置名。
2. AMLSim 的交易号写入可选列 `src_ref`，本系统重新编号为 `T…`；账户同理（可在 `dataset_meta` 中附映射文件路径）。
3. **SAR / 告警标签只能写进 `eval/`**，不得留在 data 表。
4. AMLSim 的模式名映射到 pattern：`fan_out`→P03 拆分转出、`stack`→P02 分层中转、`fan_in`→P04、`cycle`→P06；映射不到的模式先在 `enums.yaml` 中预留新代码。
5. AMLSim 的时间粒度通常比分钟粗，导入时需按规则把时间补到分钟级，补法写进导入配置并固定 seed，否则 R01 等分钟级规则没有意义。
6. 导入数据的规则阈值可能需要重调，应新建 `rules_v3.yaml`，不改 v1、v2。
