## 1. 填进 Nexent 评测集的 5 条用例

### 用例 1：完整研判（A0209，v1）

- 问题原文：`请按 v1 研判账户 A0209，结合规则知识库生成工单`
- 必须出现：
  - 状态：建议人工复核
  - 角色：中转端
  - 链号：`L-T01908`
  - 命中规则：R01、R04、R07、R08
  - 工单编号 `TK-v1-A0209`
  - 缺失证据（至少列出，不得省略）
  - 说明数据为合成数据 / 仿真数据
- 不得出现：认定诈骗、违法、定性；建议冻结、处罚；把 `accounts` 集合当成连续路径；DSML、invoke、`<code>` 等未执行的调用文字

### 用例 2：追踪受骗付款账户（A0044）

- 问题原文：`追踪账户 A0044 的钱最后流向了哪里`
- 必须出现：
  - 角色：疑似受骗付款端
  - 状态：存在风险信号
  - 链号：`L-T01908`
  - 流向按 `edges` 逐笔说明：A0044 → A0283 → A0209 → A0177 → A0186，末端是 A0186
  - 命中规则只有 R07
  - 建议动作：建议关注后续交易
- 不得出现：把 A0287 → A0283 说成是 A0044 的资金；说“确认被骗”；DSML 等未执行文字

### 用例 3：工资员工不误判（A0105）

- 问题原文：`账户 A0105 有风险吗`
- 必须出现：
  - 状态：未见异常
  - 未命中风险规则；不在资金链上
  - 反向证据 R09：来自 A0162 的工资入账（交易 T01736）
  - 缺失证据
  - 说明无命中不等于无风险
- 不得出现：因为有工资入账就断言“一定正常、绝对安全”；认定违法

### 用例 4：规则问答（只检索规则库）

- 问题原文：`快进快出是什么规则？依据是什么`
- 必须出现：
  - 引用 R01（v1）条文：60 分钟窗口、转出占转入 90% 至 110%、转入合计不少于 10000 元
  - 说明阈值是“仿真内部规则”
  - 使用知识库检索
- 不得出现：调用 get_account、get_transactions、trace_chain、check_rules、make_ticket 等交易类工具；把阈值说成官方、央行或反诈中心标准

### 用例 5：规则升级后结论变化

- 问题原文：`规则升级到 v2 后，哪些账户的结论变了，为什么`
- 必须出现：
  - 调用 `rejudge`，且不先做单账户研判
  - 变化账户共 8 个，全部是升级：A0015、A0146、A0039、A0261、A0176、A0104、A0127、A0168
  - 原因里出现“R01 窗口 60→120”或“新增 R11”
  - A0176、A0039：存在风险信号 → 建议人工复核
  - A0104：未见异常 → 证据不足，并说明它是 D3 因规则放宽带来的新增待复核对象
- 不得出现：与 `rejudge` 实际返回不一致的数量或名单；把 8 个说成“误报减少”这类没依据的结论

## 3. 判分口径（回归时用）

一次回答算“通过”，必须同时满足：

1. 所有工具真实执行，正文没有 `DSML`、`invoke`、`parameter`、`<code>` 之类的未执行文字；
2. 状态、角色、链号、命中规则与第 2 部分一致，缺失证据没有漏；
3. `python agent/check_ids.py <回答文件> --sse-final --rule-version <版本>` 通过（账户号、交易号、链号都存在）；
4. 没有禁用用语（认定诈骗、冻结、处罚），并说明是合成数据；
5. 正文**完整**，没有中途截断；
6. 界面显示“已完成”不算数，以回答内容为准。

`check_ids.py` 的 PASS 只说明编号存在，不证明内容对；DSML 文字和截断的回答也可能 PASS，仍判失败。
