## 执行摘要：为什么前一份报告的推荐可能不够

### ⚠️ 警惕"AI生成选题陷阱"

**问题1：过于宽泛的方向大家都在做**
- "惠企政策资格核验"、"上市公司年报分析" → 这些是GPT/Claude给所有人的标准答案
- 结果：100个队伍选50个相似方向，评委审美疲劳

**问题2：缺乏真实数据路径**
- 很多"高分选题"实际上数据根本拿不到
- 评委一眼看穿：合成数据 = 技术demo，不是真实业务价值

**问题3：没有从往届获奖作品中提取差异化元素**
- 往届特等奖有明确的业务纵深和数据闭环
- 简单照搬赛题文档的技术关键词 ≠ 获奖

### ✅ 本报告的差异化策略

1. **深度拆解往届获奖作品**：找出"为什么他们赢"的具体要素
2. **匹配可落地的公开数据源**：政务白皮书、行业标准、开源项目、学位论文
3. **推荐5个细分垂直方向**：足够具体，有业务纵深，不是大路货
4. **每个方向给出72小时验证计划**：3天内验证数据可得性，不行立即换

## 二、数据来源思路：从公开资源构建真实业务数据集

### 2.1 制造赛道的5层数据来源

**层级1：国标、行标、工信部公开规范**
- **来源**：国标全文平台、全国标准信息公共服务平台
- **可获取**：智能制造标准、MES功能规范、设备互联互通标准
- **用途**：业务模块定义、信息字段规范、标准版本对比

**层级2：头部工业软件厂商公开白皮书**
- **来源**：用友、金蝶、鼎捷、树根互联、海尔卡奥斯、华为云智能制造白皮书
- **可获取**：MES流程、生产工单流转、设备OEE、质量异常闭环、人员岗位职责清单
- **用途**：业务流程设计、状态机定义、字段模型

**层级3：开源项目与开源MES**
- **来源**：Gitee/GitHub上的开源MES、开源车间管理系统
- **可获取**：数据库表结构、工单状态机、审批流转逻辑
- **用途**：直接参考字段设计、业务流程实现

**层级4：知网/万方学位论文、期刊**
- **来源**：硕士论文（车间工单调度、异常预警、产线职责划分）
- **可获取**：业务流程图、需求模型、案例数据
- **用途**：文献引用、业务场景验证

**层级5：实地走访（轻量）**
- **方式**：本地制造企业、校企合作工厂参观+访谈
- **可获取**：业务流程、痛点描述（不索要原始数据库）
- **用途**：调研报告附件、真实需求验证

### 2.2 政务赛道的4层数据来源（以12345工单派单为例）

**层级1：各地政府官网、编办、政务服务局公开文件（核心）**
- **关键词**：`12345派单目录`、`权责清单`、`三定方案`、`热线退单规则`、`职责争议会商机制`
- **典型案例**：
  - 西安：42万字派单手册
  - 东营：355项派单事项清单
  - 西宁、吉安等：事项分类、主办/协办单位、边界冲突规则
- **用途**：权责知识库、事项分类树、冲突判定规则

**层级2：政务数据大赛公开脱敏数据集**
- **案例**：北京"数据要素×"大赛的12345智能派单赛题
- **可参考**：数据集字段结构（工单文本、地址、分类、历史派单、退单原因）
- **注意**：数据集本身可能不开放，但可照着字段结构仿真

**层级3：政务数字化厂商公开方案**
- **来源**：数字政通、太极、浪潮、华为云一网统管、12345热线平台方案白皮书
- **可获取**：工单流转状态机、职责变更同步机制、跨部门协同流程

**层级4：政策法规库**
- **顶层规则**：《政务服务便民热线管理办法》

### 2.3 稳妥的仿真数据集构建路线

**第一层：知识库构建**
- 从政府文件整理：权责知识库、事项分类树、冲突判定规则

**第二层：仿真工单生成**
- 用Python + Faker + 规则库批量生成
- 模拟场景：正常派单、错派、退单、职责调整后旧工单复核、交叉边界诉求
- 控制分布贴合公开统计（如某类诉求占比）

**第三层：文本素材补充（可选）**
- 少量公开舆情、政务留言板块文本，脱敏改写后作为工单文本

**第四层：标注说明**
- 文档里明确标注：**无真实市民隐私工单，数据集基于公开权责规则仿真生成，用于算法验证**

**评委认可度**：✅ 高（有公开规则支撑，业务逻辑真实，仅数据合成）

## 三、5个差异化细分选题推荐

### 推荐1：12345工单派单与职责变更核验智能体 ⭐⭐⭐⭐⭐

**为什么选这个？**
1. **往届完全空白**：政务方向往届主要是安全、应急，没有办事流程决策
2. **数据来源完全公开**：西安42万字派单手册、东营355项事项清单，够用！
3. **业务纵深清晰**：派单规则→职责变更→历史工单复核→退单原因分析
4. **评委易懂**：12345热线人人都打过，业务场景不需要解释

**核心任务**：
- 输入：工单文本、地址区域、历史派单记录、部门权责清单（多版本）
- 输出：推荐承办单位、退单风险预警、职责变更后的历史工单重新复核建议

**跨文档推理路径**：
```
工单文本 → 事项分类 → 权责清单（当前版本）→ 主办/协办单位 
         ↓
    历史派单记录 → 退单原因 → 职责争议规则 → 冲突标记
         ↓
    职责清单更新 → 受影响事项查询 → 旧工单重新判定
```

**本体构建**：
- 实体：部门、事项、权责、地址、工单、版本、派单记录
- 关系：主办、协办、职责边界、冲突规则、版本继承

**72小时验证计划**：
- **Day 1**：下载西安/东营/西宁任意一地的派单目录和权责清单
- **Day 2**：整理出事项分类树（30-50项）、部门清单（10-20个）、退单规则（10条）
- **Day 3**：仿真生成50个工单案例，手工标注正确派单和退单原因

**数据示例**：
```yaml
工单001:
  文本: "小区楼下餐饮店油烟扰民，希望整改"
  地址: "高新区XX街道XX小区"
  诉求分类: 环境保护 > 油烟噪声
  
  规则库匹配:
    - 主办: 区生态环境局（环保违法查处）
    -协办: 区市场监管局（餐饮许可核验）
    - 排除: 街道办（无执法权）
  
  职责版本: 2025-v3
  
  变更测试:
    - 2026-v1版本：生态环境局职责下沉至街道
    - 影响：工单001重新判定→主办变为街道办
```

**与往届差异化**：
- ❌ 往届：城市安全隐患分级（偏预警，不是流程决策）
- ✅ 本题：流程决策+职责版本管理+历史影响分析

**评分预测**：85-90分（数据充足、业务清晰、差异化强）

### 推荐2：制造业SOP版本变更影响追溯与复检任务生成智能体 ⭐⭐⭐⭐⭐

**为什么选这个？**
1. **往届有基础但不深入**：InspectLite做了质检，但没有深入SOP变更影响
2. **数据来源5层全覆盖**：国标+白皮书+开源MES+论文+轻量访谈
3. **业务价值直接**：SOP变更→哪些在制品需复检→证据可追溯
4. **技术契合度极高**：本体动态更新、版本管理、跨文档推理全覆盖

**核心任务**：
- 输入：工艺SOP历史版本、设备手册、检验规范、工单记录
- 输出：变更条款识别、受影响参数与工序、已完成批次复检清单、证据链

**跨文档推理路径**：
```
SOP v2.0 vs v1.5 → 变更条款识别 → 参数变化（温度、压力、时间）
                                ↓
                        对应工序 → 关联产品 → 生产批次
                                ↓
                        检验规范 → 复检条件判定 → 复检任务清单
```

**本体构建**：
- 实体：工序、参数、设备、产品、批次、标准、SOP版本、工单
- 关系：工序包含参数、参数适用产品、产品属于批次、标准约束参数、版本修订关系

**72小时验证计划**：
- **Day 1**：下载开源MES项目（如Gitee上的MES系统），分析工单表结构
- **Day 2**：找一篇制造业硕士论文（车间调度、质量管理），提取业务流程图
- **Day 3**：设计一个简化工序（如"注塑成型"），创建SOP v1.0和v2.0，标注5处变更

**数据示例**：
```yaml
工序: 注塑成型-模具安装

SOP_v1.5:
  参数:
    - 模具温度: 180-200℃
    - 保压时间: 15-20秒
  适用产品: [产品A, 产品B]

SOP_v2.0:
  参数:
    - 模具温度: 190-210℃ (↑10℃)
    - 保压时间: 18-25秒 (↑3秒)
  适用产品: [产品A, 产品B, 产品C]
  变更原因: "提高产品C的表面质量"

影响分析:
  - 受影响批次: 2025-10-15至2025-10-25期间所有产品A/B/C
  - 复检条件: 表面光泽度、尺寸公差
  - 证据: SOP_v2.0第3.2节、检验规范QC-001第5条
```

**数据来源具体化**：
1. **国标**：GB/T 19001质量管理体系、GB/T 2828抽样检验
2. **白皮书**：用友U9 MES白皮书（公开PDF）
3. **开源项目**：Gitee搜索"MES"，找带数据库设计文档的项目
4. **论文**：知网搜索"车间 SOP 变更管理"

**与往届差异化**：
- ❌ 往届InspectLite：质检工作台（偏前端展示）
- ✅ 本题：SOP版本管理+影响追溯+本体增量更新（偏后端知识演化）

**评分预测**：82-88分（技术难度高，数据需要组装但可行）

### 推荐3：电力设备维修工单与手册版本追溯智能体 ⭐⭐⭐⭐

**为什么选这个？**
1. **往届有铺垫但换角度**：武理工做了巡检前端，我们做维修后端
2. **数据来源明确**：设备厂商公开手册（如施耐德、ABB）、开源故障诊断数据集、电力论文
3. **业务价值清晰**：故障→手册版本→历史工单→下一步检查建议
4. **避开硬件**：不做无人机，只做知识管理

**核心任务**：
- 输入：设备型号、故障码、维修手册（多版本）、历史工单、备件清单
- 输出：下一步检查建议、手册版本差异、相似故障案例、备件适配性核验

**跨文档推理路径**：
```
故障码 F03 → 手册v3.2查询 → 可能原因[A,B,C]
            ↓
    历史工单检索 → 相似故障3例 → 实际原因分布：A(2例), B(1例)
            ↓
    手册v3.5更新 → 新增诊断步骤 → 重新排序检查优先级
            ↓
    备件清单 → 核验备件型号 → 替代件规则 → 库存查询
```

**本体构建**：
- 实体：设备型号、部件、故障码、症状、检查动作、处置动作、备件、手册版本、工单
- 关系：故障→部件→检查步骤、手册版本→诊断规则、备件→替代关系

**72小时验证计划**：
- **Day 1**：下载2份设备手册（如施耐德PLC手册、ABB变频器手册，官网免费）
- **Day 2**：设计10个故障场景，标注手册中的对应章节
- **Day 3**：模拟手册版本更新（如增加一个诊断步骤），测试影响分析

**数据来源具体化**：
1. **厂商手册**：施耐德官网、ABB官网、西门子官网（用户手册免费下载）
2. **故障数据**：IEEE PHM数据竞赛、NASA轴承数据集（开源）
3. **论文**：知网搜索"电力设备故障诊断"、"设备维修决策"
4. **访谈**：联系学校实验室设备管理员（不需要原始故障数据，只需要工作流程）

**与往届差异化**：
- ❌ 往届武理工：巡检图像识别+飞行控制（硬件重）
- ✅ 本题：维修知识演化+手册版本管理（软件重、知识重）

**评分预测**：80-85分（数据获取中等难度，差异化明确）

### 推荐4：医疗检查报告时间一致性与随访资料核查智能体 ⭐⭐⭐⭐

**为什么选这个？**
1. **往届有铺垫但换角度**：MAPLE做了病理问答，我们做质控和一致性
2. **数据门槛相对低**：不需要诊断权限，只做材料核查
3. **业务价值明确**：病历质控是医院刚需，不是研究项目
4. **差异化强**：不是"AI诊断"，是"资料一致性核验"

**核心任务**：
- 输入：多次检查报告、病程记录、随访表、诊疗规范
- 输出：时间冲突、单位不一致、指标矛盾、缺失检查项、随访遗漏

**跨文档推理路径**：
```
2024-03-15 血常规报告 → 白细胞 8.5×10^9/L
2024-03-20 病程记录   → "白细胞12.3"（单位缺失或错误）
                     ↓
              一致性规则 → 标记"单位冲突或数值变化异常"
```
