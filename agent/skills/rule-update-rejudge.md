# 规则更新与重判

每步只提交一个 <code>...</code> Python执行块，调用一个工具并 print 返回结果，等反馈后再继续。技能不自动授予工具权限，工具必须已绑定。版本比较无需先做单账户完整研判；仅指定单账户 v2 研判时使用 fund-chain-investigation，不自动运行全量重判。

1. 调用 rejudge(old, new)，读取 changed 与 summary。
2. 在“涉诈规则库”检索 rules_diff，说明 v1 到 v2 修改了哪些规则（如 R01 时间窗 60→120 分钟、新增 R11）。
3. 以表格列出变化账户：账户、旧状态、新状态、原因。
4. 用户要求展示新工单时，按指定账户和新版本调用 make_ticket；没有指定账户时先确认，不自行选取。仅查看已有工单由主智能体直接调用 get_ticket，不重新生成。
5. 在同一数据集上比较规则版本时，说明变化来自规则口径差异，不代表账户行为发生变化。以实际 _demo 核实来源；固定样例不能冒充全量计算。
6. summary 的覆盖数、变化数、升级数、降级数和 changed 完整名单均引用本次返回，不预填演示答案。状态、角色、链号、added/removed 和 reason 保持对应，不把升级解读为犯罪确认。
7. 需要解释某账户的反向证据时，先调用 check_rules(acct_id, rule_version=新版本)。若 changed 中有账户的新状态为“证据不足”，必须对该账户调用 check_rules 核对 counter，并逐条列出实际返回的反向命中规则、交易编号及其提供的时间、付款方/收款方和金额；不能只写“已核查”或只复述rejudge.reason。只按实际返回解释状态，不把知识库或评测答案作为账户证据。
8. 检索规则差异只用于解释条件和版本来源。检索不到如实报告；必要业务工具返回 error/code 时停止对应操作，不声称成功。工单支持证据的交易号、时间、金额和账户视角描述引用 make_ticket；具体付款方、收款方及边关系仅引用 trace_chain.edges，不将补充的方向描述称为工单原文。反向证据逐条保留交易编号，缺失证据和建议动作照实际返回展示。
9. 普通版本比较到汇总、完整变化表和规则差异解释为止，不逐户扩展交易金额、时间或命中明细。例外是用户明确要求为指定账户生成工单：必须为该工单账户列出有工具证据支持的四类量化信息（转入合计、转出比例、账户停留时间、整链跨度），缺少依据时逐项注明无法确定。先从 make_ticket 的 supporting_evidence 逐笔汇总明确列出的转入金额并保留算式；用 check_rules.metrics 引用对应链路的出入比例；用 trace_chain.duration_minutes 引用对应链路的整链跨度；账户停留时间严格按目标账户时间最晚的一笔转入至其后对应转出计算，展示起止交易及时间，不得用首笔转入替代或同时列出两种口径；整链跨度单独引用 trace_chain.duration_minutes。纯计算可以单独执行并保留算式，不可把结果归到其他账户或整条链。这些必要补查不属于额外的单账户完整研判，不重复查询画像、全量流水或生成工单。规则窗口放宽的风险只作一般性说明：可能纳入更多正常干扰场景，不能据此认定具体账户正常或误报。
