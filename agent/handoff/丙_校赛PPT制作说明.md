# 丙方校赛 PPT 制作说明稿

整理日期：2026-10-31。用途：供丙据第一周现有实现与证据制作校赛答辩 PPT。本文是内容蓝图，不是已经完成的 PPT，也不是演示视频。平台截图、最终文档和视频尚有缺口；未知的学校/队伍/姓名等信息留待填写，不要补造。

## 一、定位与制作原则

建议制作 **12 页主体 + 2 页备份**，用于约 8–10 分钟校赛汇报；如现场时长另有要求，再按主线压缩。答辩主线不是“我们做了一个聊天机器人”，而是：

> 把分散流水变成有时间与资金约束的链路证据；由 MCP 提供可核验计算，Skill 约束智能体执行和表达，最后形成带反向证据与缺口的人工复核工单。

听众看完应能回答四件事：问题是什么；流水如何成为链；Nexent、MCP、Skill、知识库各负责什么；目前仿真结果说明了什么、又没有说明什么。

视觉建议：白底、深灰正文、红色只用于待关注信号，绿色表示反向/正常场景，黄色表示中转节点。每页只放一个结论和一张主要图表。优先使用仓库生成的链路图和真实 Nexent 截图，不做无法核验的界面效果图。链路边必须画箭头并标交易编号/金额/时间；汇入画成分支，不能把账户集合画成一条虚构直线。

## 三、答辩演示串联

如 PPT 配实时演示，建议 3–4 分钟：

1. 规则问答：问 R01 v1/v2 定义，证明知识库只解释规则；不调用账户分析工具。
2. A0209/v1：展示真实链方向、状态及工单证据；并行汇入要分开画。
3. A0105/v1：工资是反向证据，不把单笔工资夸大成“绝对正常”。
4. v1→v2：展示 8 个变化账户和 R01/R11 差异；只引用重判返回，不额外推断。

演示前确认云端 `fundtrace-mcp` active、real 自检通过，发布版当前工单已重生成。失败或限流要如实记录，不用历史截图伪装成实时成功。当前正式 V9 只读 A0209 工单已在更新付款/收款方描述后复测通过。

## 四、必须保留的口径

- 一切账户、交易和效果数字都限定为“在本作品设定的仿真场景内”，明确数据集 `sim-gen_profile_v1-seed42`。
- “real 模式”指真实调用算法处理合成数据，不代表银行真实数据。
- v1/v2 是规则版本；V9 是 Nexent 智能体发布版本；恢复副本测试 V2 也是平台测试版本，三者不可混淆。
- v2 演示链专为说明规则变化设计，不证明真实场景泛化。B2 无时序基线在当前数据集上与 v2 指标相同，不宣称全面优于基线。
- 系统只给辅助研判意见，不作违法/诈骗认定，不建议冻结或处罚。
- 5 篇案例是带出处的公开报道摘要；案例 02 与 03 的上游不属于纯电信诈骗，不能统一称“电诈案例”。案例不构成当前账户证据。
- 平台评估的 0.88 与 0.924 分别对应 V5 与 V8，不是 V9 分数，也不能不加口径说明地写成准确率提升。
